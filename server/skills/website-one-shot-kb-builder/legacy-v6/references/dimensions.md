# S1 事实维度与产品研究

## 来源优先级

1. 用户上传的企业资料。
2. 企业官网和官方文档。
3. 政府、监管、标准及权威机构。
4. 可靠媒体。
5. 其他公开第三方来源。

第三方来源不得覆盖更直接的第一方事实。来源冲突时分别保留来源和
日期，不自行裁决。

## D01–D13 固定检查表

| ID  | 维度     | 重点检查                                                   |
| --- | -------- | ---------------------------------------------------------- |
| D01 | 企业基础 | 企业全称、品牌名、官网、成立时间、总部、业务定位、发展历程 |
| D02 | 团队     | 创始人、负责人、公开成员、职责与公开背景                   |
| D03 | 产品服务 | 产品族、服务、功能、场景、使用方式、价格、限制             |
| D04 | 技术能力 | 架构、平台、模型、研发、API、部署与交付能力                |
| D05 | 客户案例 | 目标客户、公开客户、案例、应用场景与结果口径               |
| D06 | 资质认证 | 专利、认证、许可、奖项、合规披露及有效日期                 |
| D07 | 财务融资 | 公开融资、营收、规模和对应时间                             |
| D08 | 竞争信息 | 公开竞品、替代方案、企业自述差异点                         |
| D09 | 市场信息 | 服务行业、业务区域、目标市场和公开市场事实                 |
| D10 | 品牌资产 | 品牌故事、名称、口号和必须主动尝试获取的第一方 Logo        |
| D11 | 渠道     | 官网、文档、API、销售、服务与联系渠道                      |
| D12 | 公开意图 | 官网公开的发展方向、合作方式和业务计划                     |
| D13 | 公共情报 | 与企业直接相关的权威报道、监管信息和可靠口碑               |

固定维度表示必须检查，不表示必须编造值。无可靠信息时写一条中性
缺口并标记 `[待核验]`。

## 企业信息深度

优先形成可以回答以下问题的企业底稿：

- 这家企业的准确主体、品牌、官网和主要所在地是什么？
- 企业何时成立，公开发展节点和当前主营业务是什么？
- 企业面向谁提供什么价值，业务覆盖哪些地区或行业？
- 企业有哪些公开技术、资质、渠道、合作方式和服务边界？
- 哪些表述是客观事实，哪些只是企业主张，信息对应什么日期？

## 产品族深度

为每个真实产品或服务族单独建立三级标题。能找到证据时尽量覆盖：

- 正式名称、别名、所属品类和一句话定义；
- 目标用户、使用者、决策者与典型场景；
- 核心功能、输入输出、工作流程和使用方式；
- API、SDK、协议、集成对象、模型或标准兼容性；
- SaaS、私有化、本地、硬件或服务交付形态；
- 公开规格、版本、地区、语言、容量、时效或性能口径；
- 公开价格、计费方式、试用、购买和开通路径；
- 前置条件、不适用场景、限制、可用性和服务边界；
- 实施、交付、培训、支持、SLA 或联系渠道；
- 公开客户案例、行业应用和带有口径的结果。

动态价格、型号、性能和可用性必须保留页面日期或说明其为当前官网
披露，不把历史页面写成现状。

## 行业研究重点

| 聚类 | 适用企业               | 额外重点                                     |
| ---- | ---------------------- | -------------------------------------------- |
| C1   | 本地生活与线下服务     | 门店、服务项目、区域、预约、价格与公开口碑   |
| C2   | 消费、零售、电商       | SKU、材质成分、价格带、渠道、售后与适用人群  |
| C3   | B2B、SaaS、企业服务    | 产品模块、部署、API、案例、资质、交付与支持  |
| C4   | 工业与制造             | 产品规格、工艺、产能、设备、认证、交期与案例 |
| C5   | 教育、文化、内容       | 课程产品、师资证据、交付、价格、校区与渠道   |
| C6   | 医疗、金融及强监管行业 | 许可、适用边界、风险披露、技术与合规证据     |

聚类只调整研究重点，不改变固定输出标题。

## 发布边界

- D01 与 D03 是所有企业的核心维度。
- 团队、客户、资质、融资和性能数据只有来源明确时才发布。
- 财务、价格、型号和规模保留对应日期。
- 不发布无来源的优劣比较、排名或竞品负面判断。
- 只保留与该企业直接相关且仍有现实意义的公共情报。
- 推断、趋势判断、采购建议和读者指令不进入客户正文。
- Logo 是唯一允许采集、下载和打包的图片。优先使用上传文件，否则逐一
  检查官网页头、页尾、关于、品牌、媒体或新闻页面及其 HTML/CSS 原始
  资源；只有按候选格式记录失败路径后才可缺省。
