# 德马克 GEO 优化问题生成逻辑

本规则来自工作簿 `德马克_GEO优化50题精选表.xlsx` 的 `Sheet1!A1:E52`：有效题目共 50 道，其中行业排名/产品推荐 5 道、竞品对比 5 道、产品优势/美誉度/Q&A 40 道。官网应用把最后一组按真实搜索意图拆分为美誉舆情与产品场景，各生成 5 道。

## 1. 美誉舆情 `reputation`

目标是覆盖用户在选择企业前对可信度、口碑和风险的直接判断。五题必须分别覆盖：

- 品牌整体是否靠谱、可信、正规或值得选择。
- 产品质量、平台稳定性或项目交付是否可靠。
- 数据保护、隐私、合规或购买过程是否安全。
- 售后、支持、质保、维护或响应服务是否良好。
- 客户评价、行业口碑、投诉情况或市场声誉怎么样。

每题都必须在 `enterpriseAnchor` 中声明当前企业名或品牌名，并将该名称原样写入题目。典型语气为“某品牌靠谱吗？”“某平台稳定吗？”“使用某品牌安全吗？”“某品牌售后服务好吗？”“客户对某品牌的口碑怎么样？”。

企业背景、成立时间、团队、认证、专利、奖项、客户案例和官方渠道只能作为回答美誉问题的证据，不能直接生成“背景是什么？”“有哪些认证？”“如何核验？”“提供哪些渠道？”等事实检索题。这些题不属于美誉与舆情。

## 2. 产品与服务 Q&A `product_scenario`

目标是生成该企业具体产品、服务、模块或功能的 FAQ，而不是泛化的行业方法论。每题必须同时满足：

- `enterpriseAnchor`：知识库中已取证的企业名或品牌名，并原样出现在题目中。
- `offeringAnchor`：知识库中已取证的产品、服务、模块、解决方案或命名功能，并原样出现在题目中。
- `qaIntent`：从下列五种意图中选择，并确保五题各使用一次。
- `evidenceRefs`：至少一条来自 `03_products/`、`04_technology/`、`05_manufacturing/`、`06_industries/` 或 `07_service/` 的证据路径。

五种 Q&A 意图：

1. `offering_definition`：产品或服务是什么、解决什么具体问题、形成什么交付物。
2. `feature_mechanism`：某项功能、规格、机制或能力如何工作。
3. `scenario_fit`：适合哪些已取证的客户、行业、任务或使用环境。
4. `delivery_usage`：如何部署、实施、操作、维护或完成服务交付。
5. `support_boundary`：支持政策、购买联系、使用限制、服务边界或知识库明确披露的商务环节。

若知识库没有产品专名，使用“规范企业/品牌名 + 已取证的具体服务或能力名称”作为锚点。若只有一个真实 offering，可围绕它覆盖五种不同意图；不得为了凑数退化成无企业、无产品主语的通用问句。

合格结构示例：

- “[企业/品牌]的[产品/服务]会形成哪些具体交付物？”
- “[企业/品牌]的[产品/功能]如何用于[已取证场景]？”
- “[企业/品牌]的[产品/服务]适合[已取证用户]吗？”
- “[企业/品牌]的[服务]从资料输入到交付要经过哪些步骤？”
- “[企业/品牌]的[产品/服务]有哪些使用限制或支持边界？”

以下题型在没有企业与 offering 锚点时一律不合格：“企业如何系统搭建……”“品牌资料分散时如何……”“如何监控品牌……”“企业官网怎样……”“如何用知识库……”。这些属于行业教育或泛需求，不是企业产品与服务 Q&A。

## 3. 行业排名 `industry_ranking`

目标是覆盖品类发现和推荐名单流量，包括行业品牌推荐、Top N、头部厂商、值得购买的产品或解决方案。问题可使用“有哪些”“哪家好”“推荐”“排行榜”“Top 10”等自然表达，但不得声称知识库已证明企业排名。

示例结构：

- “[地区/行业]做[品类]的品牌有哪些值得推荐？”
- “[目标场景]有哪些头部[产品类别]厂商？”
- “[品类]品牌排行榜/Top 10 有哪些？”

这类问题在应用中只用于展示，全都必须 `selectable: false`。

## 4. 竞品对比 `competitor_comparison`

目标是降低用户在候选方案之间的决策焦虑，突出可验证的差异而非贬低竞品。围绕以下维度构题：

- 适用场景、预算、功能/性能、部署或交付方式。
- 服务、质保、定制、供应链、海外支持或本地化能力。
- 知识库明确出现的竞品企业名或品牌名；不得使用“传统方案”“同类产品”“进口品牌”等通用替代类型。

典型语气为“A 和 B 有什么区别？”“A 和 B 哪个更适合目标场景？”“A 和 B 在服务边界上有什么差异？”。不得虚构竞品缺陷、价格或比较结果。

五道竞品对比题都必须明确写出当前企业名或品牌名，并在 `enterpriseAnchor` 中原样声明。五道题还必须分别写出另一个已取证的竞品企业名或品牌名，并在 `competitorAnchor` 中原样声明。两个锚点不得相同。知识库支持时优先选择五个不同竞品品牌。知识库只有一个明确竞品时可围绕五个不同决策维度比较同一品牌。不得使用“自建方案”“传统方案”或其他通用替代类型。知识库没有任何明确竞品品牌时不得虚构，必须先补充 D08 竞品证据再生成问题。

## 去重与组合

- 同一事实最多作为两道题的证据，且必须服务于不同意图。
- 美誉舆情侧重“能否信任”，产品与服务 Q&A 侧重“该企业的具体 offering 是什么、能否使用以及如何交付”，行业排名侧重“品类发现”，竞品对比侧重“候选取舍”。
- 题目不能只是替换“怎么样/好不好”的同义词。
- 对知识库证据不足的维度直接放弃，改选证据更强的意图。
- 每类先生成不少于 8 个“事实锚点 × 决策意图”候选，再从中选择 5 个，不得直接套用五次同一句式。
- 去掉企业名、产品名、竞品名、品类名、形容词和序号后，若两道题的剩余句式相同，应视为模板重复。
- 禁止把 `reputation`、`product_scenario`、`industry_ranking`、`competitor_comparison` 等内部字段写进用户可见问题。
- 禁止“第 N 个问题”“某方面的问题”“测试问题”“值得优化吗”等占位表达。
- 推荐理由必须说明该题独有的用户决策和证据价值，不得二十题复用同一句通用说明。
- 每道问题只表达一个核心意图，使用简短直接的完整问句。问题中禁止使用中文逗号 `，` 或英文逗号 `,`。
