# FrontMind GEO 付款后签约与账号开通设计

## 结论

FrontMind 当前是独立网页应用，电子签服务优先采用 **e签宝 SaaS API V3**。它提供流程模板、PC/H5 自适应签署链接、实名认证、签署状态查询、回调与签署文件下载，适合把现有月度服务合同做成可自动填充的模板。

腾讯电子签作为第二选择。如果以后入口主要位于微信小程序或企业微信，可重新评估腾讯电子签；普通 H5 签署链接不能直接嵌入微信小程序，需要走其小程序跳转接口。法大大能力满足需求，但公开接口、回调和沙箱资料的可审计程度暂时不如前两者。

## 客户流程

```text
选择月度服务
  → 审阅合同模板
  → ZPay 付款
  → 服务端确认订单
  → 填写企业与签约经办人资料
  → 从锁定模板生成正式合同
  → 电子签平台实名认证并签署
  → FrontMind 服务端复核签署状态
  → 客户设置 FrontMind 账号与密码
  → Agent 创建 role=user 的账号
  → 进入执行
```

支付平台的页面跳转只用于返回 FrontMind。支付状态必须以验签通过的 ZPay 异步通知或服务端订单查询为准。电子签页面跳回也不能直接视为签署完成，必须由回调验签并主动查询签署流程状态确认。

## 状态机

正式服务订单应持久化以下状态，不应只依赖浏览器中的项目 token：

| 状态 | 客户看到的内容 | 服务端允许的下一动作 |
| --- | --- | --- |
| `payment_pending` | 收银台与订单状态 | 核验付款 |
| `profile_required` | 企业与经办人资料表单 | 创建不可变合同快照 |
| `signature_required` | 合同摘要、查看合同、去签署 | 接收回调并主动查询 |
| `account_setup_required` | 用户名与密码表单 | 调用 Agent 开户接口 |
| `provisioning` | 正在分配账号 | 幂等重试开户 |
| `active` | 工作台入口与执行状态 | 创建项目任务 |
| `failed` | 可恢复错误与人工处理入口 | 按错误类型重试 |

一笔已付款订单只能绑定一个有效合同流程；同一合同只能创建一次用户账号。状态转换必须由服务端完成。

## 签约资料

FrontMind 只收集生成合同所需的最小信息：

- 企业完整法定名称；
- 统一社会信用代码；
- 合同联系地址；
- 签约经办人姓名与职务；
- 经办人手机号与邮箱；
- 经办人已获企业授权的确认。

身份证号、刷脸信息、银行卡要素与企业实名认证材料由电子签平台直接处理，不进入 FrontMind 表单、项目 token 或日志。

合同模板动态填充：

- 客户签约主体；
- FrontMind 签约主体；
- 服务订单号、支付时间与金额；
- 所选 GEO 问题原文与问题类型；
- 一个月服务周期与服务范围；
- 合同模板版本；
- 签约经办人信息。

正式合同生成后保存模板版本、PDF SHA-256、电子签流程 ID 和合同 ID。签署完成后保存签署时间、签署文件对象存储键和证据报告 ID，不接受任意外部下载 URL 作为可信证据。

## 账号创建

FrontMind Agent 提供私有接口：

```text
POST /api/internal/provisioning/users
```

调用要求：

- 仅官网服务端可调用；
- 使用独立 `FRONTMIND_PROVISIONING_SERVICE_TOKEN`；
- 每笔订单使用稳定 `Idempotency-Key`；
- 请求必须包含相互匹配的已付款订单和已签合同证据；
- 请求体不接受 `role`，Agent 固定创建 `role=user`；
- 用户密码只在 TLS 请求中短暂存在，Agent 立即使用现有 scrypt 逻辑哈希；
- 密码、密码哈希和服务令牌不写入订单、合同、开户账本或日志；
- 订单号、交易号、合同号和幂等键均有唯一约束。

建议幂等键：

```text
geo-service:{zpay-out-trade-no}:account-v1
```

## 上线前配置

1. 完成服务合同的法务定稿。
2. 在 e签宝创建企业开发者应用和沙箱应用。
3. 把正式合同制作成流程模板，配置动态字段和双方签署区。
4. 配置 FrontMind 回调域名、签署完成跳转地址与模板 ID。
5. 在官网服务端保存 e签宝 App ID、密钥和模板 ID，不下发浏览器。
6. 为官网与 Agent 配置相同的开户服务 token，并应用 Agent 数据库迁移。
7. 完成一笔沙箱测试：付款确认、合同生成、签署完成、账号创建、重复回调幂等和拒签/过期恢复。

## 法律与证据链

普通企业服务合同可以使用电子签名，但只有满足可靠性要求的电子签名才与手写签名或盖章具有同等法律效力。产品需要保留身份认证、签署意愿、合同原文完整性、签署时间、流程事件与签署文件归档。合同条款、经办人授权范围与争议处理仍需法律顾问审核。

- [《中华人民共和国电子签名法》](https://www.npc.gov.cn/zgrdw/npc/xinwen/2019-05/07/content_2086835.htm)
